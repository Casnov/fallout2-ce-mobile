# Этап 7: мобильное поведение

Цель — пользовательский путь Android с общим мобильным интерфейсом и
распознавателями жестов. Браузерный слой отвечает за окно, разрешение звука,
системную клавиатуру и прерывания, не распознаёт игровые жесты повторно.

## Уже было реализовано к началу этапа

| Возможность | Реализация |
| --- | --- |
| Тап, удержание, радиальное меню, перетаскивание, прокрутка, панорама, масштаб, прицеливание | Общие `touch.cc`, `touch_controls.cc`, `mui.cc` и мобильные экраны; один путь DOM → SDL → C++ |
| Размеры и вырезы | `svga.cc`/`hud_layout.cc` используют реальные canvas, DPR и CSS safe area; размеры конкретного iPhone не зашиты |
| Пропорции | `createGameViewport` вписывает canvas с постоянным отношением сторон; клавиатура накладывается поверх игры |
| Ввод | Общие редакторы имени/описания сейва; DOM-поле над игровым полем, Unicode/IME и Enter без повторной передачи текста через SDL |
| Звук | Один AudioContext разблокируется кнопкой «Начать игру» и передаётся SDL; восстановление при возвращении и пользовательском действии |
| Обмен сейвами | Общий менеджер поверх приостановленной сессии, автоматический возврат после успеха/отмены; доступ к данным передаётся между движком и worker |
| Память ресурсов/сейвов | Ленивое чтение, кэш ресурсов 64 МиБ, пользовательских блоков 16 МиБ; вся библиотека не загружается при запуске |

Сохраняются ранее принятые особенности веба: короткий экран «Начать игру»
для разрешений браузера, предложение повернуть телефон и запасной прямой
тап по текстовому полю, если iOS не открыла клавиатуру программно. Установка
PWA необязательна. Новых пользовательских отличий от нативного пути на этом
этапе не вводится.

## Исправления

1. **Отмена касания.** В закреплённом SDL 2.32.0 обработчик Emscripten
   преобразует DOM `touchcancel` в обычный `SDL_FINGERUP`. Новый мост окна
   записывает отмену; движок на своей стороне сбрасывает очередь SDL,
   распознаватель карты, захват MUI и ожидающие команды. Сбрасываются также
   уже отпущенные, но ещё не обработанные тапы. MUI завершает захват за
   пределами экрана через существующий механизм, не нажимая кнопку.
2. **Фон и перекрытия.** SDL передаёт скрытие документа как `HIDDEN/SHOWN`,
   а существующий нативный путь реагировал на потерю/возврат фокуса.
   Мост согласует видимость, фокус и перекрытия с тем же нативным обработчиком:
   пауза, сброс ввода, настройки, восстановление экрана и звука. Обработчик
   Android извлечён в функцию без изменения его действий. Прерывание
   сохраняется даже при полном цикле ухода/возврата между двумя опросами
   замороженного браузером движка. Веб-обработчики
   DOM не вызывают приостановленный Asyncify-стек.
3. **Поворот.** Изменение геометрии/DPR и ориентации отменяет старые касания
   и обновляет layout/safe area. Это включает разворот на 180°, когда размеры
   могут остаться прежними. Обычное изменение видимой области клавиатурой
   при неизменном canvas не отменяет ввод. Поворот туда и обратно с открытой
   клавиатурой сохраняет исходную необрезанную поверхность игры.
4. **Прерывание звука.** Переход существующего AudioContext из `interrupted`
   в `suspended` вызывает одну попытку восстановления. Пауза обмена и скрытая
   страница остаются приоритетными; повторных таймеров, нового аудиографа и
   изменений буфера нет. Отказ браузера по-прежнему допускает восстановление
   обычным касанием.

## Проверки и границы доказательств

- `node --test os/web/test_browser.mjs`: 19 проверок геометрии, ввода/IME,
  отмены, фокуса, видимости, перекрытий и AudioContext.
- `python3 os/web/test_touch_interruptions.py`: настоящий C++ распознаватель
  и MUI — обычный тап, отмена ожидающего тапа, отмена pinch, повторный ID
  пальца, отпускание MUI при наличии/отсутствии оставшегося SDL-захвата.
- `test_files_ui.mjs` + `test_stage6.mjs`: 28 проверок существующего обмена,
  возврата в сессию и обработки ошибки передачи скачивания.
- `test_lifecycle.py`: настоящий WASM/Asyncify — контракт флагов с настоящим
  JS-мостом окна и завершение runtime с освобождением и возвратом к запускателю.
- Собраны Release WASM и нативный macOS движок с общими изменениями ввода.
- Сквозная проверка настоящего движка, сборка `b295b3f2`, на отдельном
  localhost-origin с RPU: синтетические DOM blur/focus между кадрами
  выполнили нативную контрольную запись и возврат без перезапуска;
  DOM touchstart/touchcancel по быстрому сейву не создали записи, а обычный
  touchstart/touchend по той же кнопке создал её. Это проверка пути
  DOM → SDL → C++, не доказательство физического мультитача iPhone.
- На реальной RPU-сессии проверены быстрые сейвы/загрузка/перезапуск,
  нативная пауза, экспорт с проверкой CRC ZIP, автоматический возврат,
  отмена импорта с восстановлением звука и writer-доступа. Измеренные кэши
  не превысили лимиты 64/16 МиБ; WASM heap в этих сценариях — 87 556 096
  байт. Это не измерение всей памяти процесса и не длительный прогон iOS.
- iPhone 17/iOS 27 Simulator: проверены портретный запускатель и доступность
  Play после поворота в обычной вкладке Safari. Полный запуск движка не
  завершён: на Mac закончилось свободное место. Симулятор остановлен,
  исходные игровые данные сохранены. Фон/блокировка/звук iOS ещё требуют
  проверки на физическом устройстве.

Эти проверки не доказывают качество аудио, системной клавиатуры и
мультитача на физическом iPhone. Этап требует заключительного прогона
[mobile-recheck.md](mobile-recheck.md). Треск Redmi и Enter Яндекс-клавиатуры
остаются ранее отложенными Android-задачами. Холодный офлайн-запуск относится
к этапу 8, обновление оболочки — к этапу 9.
