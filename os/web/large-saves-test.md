# Большой ZIP: короткая проверка на iPhone

Сейчас iPhone недоступен; этот тест выполняется позже. Новая реализация остаётся
отдельной проверочной сборкой. В обычной игре по прежнему адресу хранилище пока
не переключено. Переустанавливать игру/ярлык и выбирать игровой ZIP не нужно.

Открыть [отдельный тест ZIP](https://ADDRESS-FROM-https-test.py/large-zip-probe.html)
в Safari. Mac должен бодрствовать. У теста нет доступа к IndexedDB игры/сейвов:
он использует отдельную временную папку OPFS. Подготовленный ZIP — примерно
4.02 ГиБ, без сжатия, со случайным блоком 256 КиБ, повторённым в файле. Для ZIP
и копии в «Файлах» нужен запас примерно 9 ГиБ свободного места.

1. Нажать **«Создать ZIP больше 4 ГиБ»**. Оставить страницу открытой до готовности.
2. Нажать **«Сохранить ZIP»** и сохранить в **«Файлы»**. Если системное меню не
   предлагает сохранение, использовать **«Скачать ZIP»** и записать, что произошло.
3. Вернуться на страницу, выбрать полученный ZIP в поле проверки, затем нажать
   **«Скопировать отчёт»** и прислать результат. Проверка размера и крайних записей
   проверяет передачу большого файла; полная CRC-проверка здесь не заявляется.
4. Нажать **«Удалить временные файлы теста»**. Отдельно удалить полученный ZIP
   из «Файлов» (и «Недавно удалённых», если нужно сразу вернуть место).

Если Safari закрыл страницу или выдача ZIP не сработала — достаточно сообщить
шаг и поведение. Созданный тестовый файл останется в отдельной папке до кнопки
очистки; игровые файлы и сейвы не меняются. Результат большого файла желательно
повторить из ярлыка Home Screen; обычная вкладка тоже должна поддерживаться.
Кнопка **«Проверить 70 000 файлов»** дополнительная, для раннего теста не нужна.

После принятия этой проверки переключим прежний адрес на новую сборку и одним
коротким прогоном проверим реальный прогресс: миграция без игрового ZIP →
экспорт всех сейвов → восстановление одного тестового слота → закрытие/запуск →
загрузка. Замену всей реальной библиотеки без готовой резервной копии не проверять.
